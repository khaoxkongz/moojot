# Data and API coverage for the mobile redesign

Codebase inspection dated 1 October 2569 (2026), for [the coverage task](../issues/07-data-api-coverage.md). Requirements come from [handoff README](/Users/computer/Downloads/design_handoff_moojot_app/README.md) and [the prototype](</Users/computer/Downloads/design_handoff_moojot_app/Moojot Home.dc.html>). Coverage includes every main screen and flow. This is source evidence, rather than physical-device validation of the redesign.

## Agreed scope

Read the decisions for [platforms](../issues/01-device-validation.md#answer), [data meanings](../issues/02-finance-data-model.md#answer), [undo](../issues/03-delete-undo.md#answer), and [slip lifecycle](../issues/04-slip-reading-lifecycle.md#answer) before defining contracts. Prototype KTC 4821, 12:00/00:05, and TODAY use simulated values. Do not use them as actual user data.

The table distinguishes three cases:

- Reuse: data and operations exist, while screens still need changes.
- App changes: existing operations can provide the result.
- Data/contract changes: current ownership or conditions cannot provide the required result.

A screen can contain all three cases. A gap does not always require a new endpoint.

## Largest planning effects

1. Entries already support soft delete/restore. Budgets, rules, categories, and tags lack complete identity/relationship restoration. Linked-budget deletion already exists. Undo is the main gap.
2. Recurring rules lack card data. Day edits may add past entries because generation uses the edited rule from startsOn. Edits must affect the next occurrence.
3. Reuse slip reading, saving, and deduplication. Add result rows, pending work, selected-image retry, and manual entry from failed results.
4. Current slip data lacks complete bank, card, counterparty, and actual transaction-time evidence. createdAt supplies recording time, rather than slip time.
5. Existing unbounded, paginated listTransactions supports all-month search. Amount matching is missing. One page cannot represent complete results.
6. Installed Better Auth returns INVALID_EMAIL_OR_PASSWORD for unknown email and wrong password. Provide sufficient contract information before displaying separate handoff errors. Do not guess from one error.

The pending-loader and calculator links use historical Git revisions. Later redesign work deleted those files.

## UI/state work without inherently new APIs

Colors, Regular fonts/system numbers, dimensions, radii/shadows, safe areas, button sizes, motion, keypad state, and draft comparison are app work. So are period offset, wallet selection, toast, stacked sheets, FAB, and navigation.

Inspect [typography](../../../apps/native/components/ui/typography.tsx), [fonts](../../../apps/native/constants/fonts.ts), [theme](../../../apps/native/constants/theme.ts), [stack](<../../../apps/native/app/(app)/_layout.tsx>), and [tab layout](<../../../apps/native/app/(app)/(tabs)/_layout.tsx>) before shared components.

FinanceTransaction/Category/Tag/Budget/RecurringRule/Setting already exist in [finance.prisma](../../../packages/db/prisma/schema/finance.prisma). Prototype `wallet` is a UI choice. It does not establish a need for a new wallet entity, especially with bank grouping.

Plan unfinished-onboarding sign-in through [the existing guard](../../../apps/native/app/_layout.tsx). The shorthand signin→Home does not authorize skipping unfinished steps. Report limitations if the new flow cannot meet its promises.

The handoff identifies `statement` as a source. It adds no statement/PDF upload flow. Features assigned to a later round remain outside scope. Enums or “coming soon” copy do not create new work.

## Product questions and engineering decisions

- [Recurring resume](../issues/09-recurring-resume.md#answer) now skips intentional paused dates and resumes at the next occurrence. Correct the generator's potential pause-period backfill.
- [First-card identification](../issues/10-first-credit-card.md#answer) provisionally uses name and last four for future selection. This optional flow awaits review with actual card users.

Pending-work storage, restoration mechanisms, endpoint structures, and components are engineering decisions under approved requirements. The user should not substitute for factual inspection. This table supplies spec input. It does not claim complete current implementation.

## Acceptance evidence required in the spec

- More than 1,000 entries: complete all-month search, counts/totals, usage counts, and card totals.
- Amount matching and Thai bank names. Exact name/last-four card scope with multiple cards.
- Month starts 29–31, Summary/budget/trend bounds, and spending exactly equal to the limit.
- Cascade deletion/undo with complete identity/references, preserved other edits, failures, and conflicts.
- New-rule backfill, next-only edits, resume policy, and editor→rule without duplicate original entry.
- Slip work after restart/>30 days, missing permission/photo, no incomplete resend, temporary retry, and manual/in-flight deduplication.
- CSV 10 columns, Thai BOM, wallet labels, known/unknown actual time, and matching client/server formats.
- Auth errors/onboarding guard, loading/error/empty states, and iOS keyboard/safe-area/layout. Defer Android verification under the latest instruction. iOS results do not establish Android results.

Earlier passing tests do not establish these new behaviors. Implementation work needs checks matching the new results.
